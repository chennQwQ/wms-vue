# 参考前端功能对齐设计

## 目标

以 `/home/chen/projects/课程资料/源代码/前端` 为最低功能基线，将当前项目中缺失或不完整的货品管理、仓库管理和监控大屏能力补齐，同时保留当前项目已有的批次管理、图片 URL 兼容和其他增强实现。

验收分为两个阶段：第一阶段保证代码功能完整，并通过单元测试、Vue/TypeScript 类型检查和生产构建；第二阶段连接现有后端，逐接口完成页面联调。

## 对齐原则

- 采用语义差异合并，不整目录覆盖参考代码。
- 当前项目已有功能优先保留；参考代码只作为缺失功能的来源。
- 保留工作区内所有既有未提交修改，不修改与本次范围无关的文件。
- 不照搬参考代码中的明显缺陷，例如未定义方法、错误权限码、无效导入、调试日志、硬编码远程样式地址或被误注释的请求。
- 页面结构、API 封装和权限标识沿用当前 JeecgBoot Vue3 项目的现有模式。
- 新增的纯逻辑优先抽成可测试单元；页面交互通过类型检查和生产构建兜底。

## 范围与架构

### 货品管理

核对货主、商品分类、商品品牌、商品、商品图片、承运商和包装材料模块。每个模块按 `*.api.ts`、`*.data.ts`、列表页和表单/弹窗四层检查，补齐查询、增删改查、批量删除、导入导出、高级查询、树形分类加载、文件预览/下载及关联选择等能力。

商品列表恢复条码打印入口。打印仅针对已勾选商品；无选中项时给出明确提示。打印数据使用当前表格选中记录和现有 `productbarcode-panel.js` 模板，不保留参考实现中的示例数据、未使用的 Lodop 分支或硬编码外部打印 CSS。当前已有的商品图片查看、文件 URL 规范化和批次管理保持不变。

### 仓库管理

核对仓库、库区和储位模块，补齐 CRUD、批量操作、导入导出、仓库启停、仓库—库区—储位联动选项及表单回显。

储位列表恢复条码打印能力，但使用储位自身权限标识和独立、可维护的打印数据映射；不复制参考代码中指向商品权限且缺少 `print` 实现的按钮。若现有模板不能表达储位标签，则新增聚焦于储位条码的本地模板，不依赖远程资源。

### 监控大屏

核对 `src/views/dashboard/bigscreen` 与参考大屏的入口、组件和数据请求，保留当前项目中更完整的实现。补齐仓库选择、统计卡片、待办任务、库存分布和入库趋势的数据流，确保请求参数携带当前仓库标识。

大屏接口失败时保留页面结构并回退为空数据，不让单个图表请求阻断整个页面。移除会导致重复或错误请求的参考代码片段，保留现有组件边界。

## 数据流与错误处理

列表页通过现有 `useListPage` 和 API 模块请求数据；表单弹窗通过现有 `useModal`、`useForm` 约定提交并触发列表刷新。关联选择在编辑回显时加载所需选项，避免只在新增流程可用。

打印流程为“校验选择 → 映射标签字段 → 载入本地模板 → 调用 `sv-print`”。空选择、模板初始化失败和浏览器打印异常均通过项目消息组件反馈，不静默失败。

大屏各数据块独立请求和更新；失败时记录可诊断信息并为对应卡片提供空数组或零值，不覆盖其他成功数据。

## 测试与验收

第一阶段验收：

- 为打印数据映射、文件 URL、树数据或其他新增纯逻辑补充 Jest 测试。
- 执行项目 Jest 测试集并修复本次变更引入的问题。
- 使用项目现有 Vue/TypeScript 工具执行类型检查；若缺少脚本，则直接调用本地 `vue-tsc`。
- 执行生产构建，确认所有组件、动态导入、模板和样式可被打包。
- 对参考文件清单再次进行语义核对，确保每项功能已实现、明确由当前增强替代，或被判定为参考缺陷而不采纳。

第二阶段验收：

- 启动前端并连接现有后端。
- 按货品、仓库、大屏顺序验证列表查询、表单提交、删除、批量操作、导入导出、文件处理、打印和图表请求。
- 对接口路径、参数名、响应形状及权限问题逐项修复，并记录后端不可用或数据缺失造成的阻塞。

## 非目标

- 不删除或重写当前项目独有的商品批次模块。
- 不进行与三个目标模块无关的全项目重构。
- 不把参考代码中的注释功能、示例数据或失效实现自动视为正确实现。
- 第一阶段不要求后端服务可用；后端联调属于静态验收通过后的独立步骤。
